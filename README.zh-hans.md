# MQTT

用 WiFi 连上 MQTT broker，和 O Bricks 网页的仪表板、或其他设备互传数据。数据的格式是“主题＋数据”，数据是 JSON（例如 `35`、`[0.5, -0.2]`、`"hello"`），和仪表板一样。

主机要有 WiFi，例如 Raspberry Pi Pico W、Pico 2 W。

## 搭配仪表板

1. 主机的程序：先放“**连上 WiFi**”，再放“**连上 MQTT broker**”（默认是 `broker.hivemq.com`，和仪表板的默认一样）。
2. 仪表板：按标签栏右边的“**连接**”，broker 用默认的 HiveMQ，按连接。
3. 两边的**前缀要一样**（都不填也可以）。
4. 仪表板的控制组件（摇杆、滑杆、按钮、开关）发送的主题，主机用“**MQTT 主题 … 的数字**”、“**MQTT 主题 … 有新数据？**”读；主机用“**MQTT 发送**”发送的数据，仪表板的数值显示、折线图就收得到。

| 仪表板组件 | 发送的数据 | 主机这样读 |
|---|---|---|
| 滑杆 | 数字，例如 `70` | MQTT 主题 robot/speed 的数字 第 1 个 |
| 摇杆 | `[x, y]`，-1～1 | x 是第 1 个、y 是第 2 个 |
| 按钮 | 按下 `1`、放开 `0` | MQTT 主题 robot/stop 有新数据？ |
| 开关 | 打开 `1`、关掉 `0` | MQTT 主题 robot/led 的数字 第 1 个 |

## 积木

- **连上 WiFi 名称 … 密码 …**：最多等 15 秒，在控制台打印 IP。
- **连上 MQTT broker … 前缀 …**：前缀选填。断线时会自己重连。
- **MQTT 发送 主题 … 数据 …**：数字、文字、是／否都可以。
- **MQTT 主题 … 有新数据？**：收到新数据时是“是”一次，放进“如果”用。
- **MQTT 主题 … 的数字 第 … 个**：最后收到的数字；数据有好几个数字时取第几个。还没收到时是 0。
- **MQTT 主题 … 最新的数据**：最后收到的数据（数字、文字或列表），还没收到是 None。

程序用到的库（`obricks_mqtt.py`、`mqtt_simple.py`）会在运行、下载程序时自动写到主机上项目文件夹的 `lib/`，不用自己复制。

读数据的积木每次执行时会顺便处理收到的消息，放在“重复执行”里就好，不用另外写收消息的程序；第一次读的主题会自动订阅。

## 注意

- **WiFi 密码会写在程序里**：分享项目或示例前记得删掉。
- **公开 broker 是大家共用的**：任何人都可能看到你发送的数据、也可能发送数据进来，不要传敏感数据；想避免和别人的主题撞在一起，可以加前缀（例如 `myclass/team1`），仪表板也要用一样的前缀。
- 主机用 MQTT 的 TCP 1883 连接（仪表板在浏览器里用 WebSocket），连的是同一个 broker，所以可以互传。
- 固件有 `umqtt.simple` 就用固件的；没有的话用这个扩展附的一份（micropython-lib 的 umqtt.simple，MIT 许可）。
